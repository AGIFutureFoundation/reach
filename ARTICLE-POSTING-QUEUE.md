## 3 · Execution model

- **Phones execute in-app** per FLEET-EXPANSION.md §2.2/§6: each phone holds its desk's accounts signed in; posts are made in the native app (or the account's web surface where the fleet plan allows), never via bulk tooling. Account-setup work (profile fills, link fields, creations still in flight in §1) runs on the same phones, ahead of that account's first post.
- **Pacing law — binds the ACCOUNT, not the device** (FLEET-EXPANSION states this plainly; five phones never multiply a cap):
  - One platform at a time, network-wide.
  - ~2 minutes minimum between posts on the same platform.
  - ≤25 actions per platform per day, network-wide; this queue's own working cap is tighter: **≤3 article posts per account per day**.
  - First warning from a platform (rate limit, action block, checkpoint) = **full stop on that platform for the day**, logged in §6 with the warning text.
  - A post that fails or is rejected is **not** retried the same day.
- **The distribution calendar is the dated spine.** The Nov 13–25 calendar (distribution-engine-2026-11/CALENDAR.md) already carries dated posts (P-items + daily episode templates T-1/T-2/T-3). This queue **fills the calendar's article-shaped gaps** — days and surfaces where the calendar has no article post — and **continues the rotation past Nov 25** on the same pattern. Where a calendar slot and a queue slot would land on the same account on the same day, the calendar slot wins and the queue slot moves a day.
- **Joiner rule:** an account in §1 marked ⏳ joins the rotation **the day after** it verifies live (login saved / creation completed / session restored), starting with its queue position 1 — it does not jump the queue to catch up.
- **Already posted — respected, never repeated:** distribution Day 1 (Nov 12): P-23 (FB BuilderSpace), P-12 (FB Ask Humanity) published. Day 2 (Nov 13): **P-21** (FB BuilderSpace — Ship It Weekend Ep 1), **P-02** (IG Foundation — The Foundation Ep 1), **P-24** (FB SmartCiti.X — game post) published; **P-10** (IG Fellowship) BLOCKED on the missing @agifellowship login; T-1/T-2/T-3 held (no episodes published that morning). Those were episode posts, not article posts — the article rotation below starts fresh, but no account repeats a same-day second post on a surface that already carried one.
- **Logging:** every executed post is written into §6 of this file **in the same run** — account, article ID (§2), date/time PT, live post URL, copy version (the §4/§5 draft ID as approved). No log line, no next post on that account.
